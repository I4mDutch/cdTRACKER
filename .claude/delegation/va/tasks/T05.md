## Decisions already made
- Vite dev server proxies `/api` → `http://localhost:3000`. All requests `credentials: 'include'`; POST/DELETE send `X-Requested-With: va-web` and `Content-Type: application/json`.
- `src/api/client.ts`: one typed function per route (e.g. `getSummary(filter): Promise<SummaryResponse>`), throws `ApiClientError { status, code, message }` parsed from `ApiError`. Filters serialized as query params, omitting empty values.
- State: plain React hooks; write a small `useApi(fn, deps)` hook returning `{ data, error, loading, reload }`. No state library, no CSS framework, no component library.
- Global filter bar (agent, map, queue, patch, date from/to, last-N) stored in URL search params so views are shareable/bookmarkable; options from `GET /api/filters/options`.
- Routing (react-router `createBrowserRouter`): `/` Overview, `/agents`, `/maps`, `/insights`, `/matches`, `/matches/:matchId`, `/settings`, `/p/:token` (public, no app chrome besides notice). Signed-out users see a landing with "Sign in" (and "Try demo" → `POST /api/dev/login` when `me.demoMode`).
- Styling: one `src/styles.css` with CSS variables, original dark-neutral theme (do NOT copy Riot or tracker.gg visuals; no Riot logos). Desktop-first, usable at 375px width.
- Formatting helpers in `src/format.ts`: percentages 1 decimal, K/D 2 decimals, `—` for null with `title="Not available from the data source"`.

## Requirements per view
- **Every data view**: loading, empty ("No matches for these filters"), and error states. Show "N matches · <from> – <to>" context.
- **Overview**: cards — matches analyzed, win rate (with Wilson interval in tooltip), K/D, latest trend direction, Analyzer Score card **only when** `score.available` (else a muted card explaining why). Key findings panel: top ≤3 non-dismissed findings. Win-rate & K/D trend line charts (Chart.js line, labelled axes, window size in title). Recent matches table.
- **Agents / Maps**: sortable tables (click header; `aria-sort`) with matches, win rate, K/D, ACS, ADR, Δ vs baseline (`winRateDelta` with +/- sign **and** an arrow glyph/text, not color alone), and a "Low sample" badge when `lowSample`. Maps view additionally offers a heatmap-style grid (map × metric) with an accessible table toggle; cells show text values. No "Map Rating"/"Map Impact Score" anywhere (not in v1).
- **Insights**: list findings with summary, recommendation, metric value vs baseline + baselineLabel, sample matches/rounds, evidence badge (text label), expandable "How was this generated" showing `method` and analysisVersion, links to contributing matches, buttons Dismiss / Not useful / Useful → `POST /api/insights/feedback`. Dismissed shown collapsed in a separate section.
- **Matches**: paginated table (map, agent, result W/L/D as text, score `roundsWon–roundsLost`, K/D/A, ACS, ADR, date); excluded matches show their reason. Row links to detail.
- **Match detail**: summary + team results; round timeline table only if `rounds.length > 0`, else notice "Round-level data wasn't provided for this match". A "Data sources" section listing `fieldSources` (riot / calculated / unavailable). Never show other players.
- **Settings**: link state (all `LinkState` values have readable labels), consent checkbox required before "Link Riot account" (`POST /api/riot/connect` then `window.location.assign(redirectUrl)`), "Sync now" (`POST /api/sync`, poll `GET /api/sync/:jobId` every 2s until done), CSV export link (`/api/export.csv` with current filters), share links (create with field checkboxes + expiry, list, revoke; show the url once), Unlink & delete data (confirm dialog), sign out.
- **Score**: wherever shown, include `SCORE_DISCLAIMER`, formulaVersion, coverage %, and a component breakdown (label, weight→effectiveWeight, normalized value or "unavailable" + note). Also add a small explicit line: "Riot Performance Score: not available from the Riot API".
- **Public page `/p/:token`**: card with displayName, match count, date range, and only the fields present; disclaimer.
- **Footer on every page**: `RIOT_NOTICE` from `@va/shared`.
- Accessibility: semantic tables with `<caption>`, labelled form controls, visible focus, keyboard-operable sort/toggles, chart `aria-label` + a visually-hidden data table fallback.
